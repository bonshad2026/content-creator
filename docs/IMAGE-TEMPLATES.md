# تعریف قالب تصویری

هر قالب یک فایل JSON در `templates/image/` دارد. قالب فعلی `blue-splash.json` است؛ پرامپت کامل تست‌شده داخل فیلد `prompt` قرار دارد. موتور در هر تولید، فقط عکس محصول و همین متن را به GapGPT می‌فرستد. نمونهٔ نمایشی همراه درخواست تولید ارسال نمی‌شود.

```json
{
  "id": "blue-splash",
  "version": 1,
  "name": "اسپلش آبی",
  "type": "image",
  "enabled": true,
  "category": "beauty",
  "subcategories": ["skincare", "deodorant"],
  "platforms": ["instagram"],
  "goals": ["introduce", "sale"],
  "sample": "/templates/blue-splash/sample.webp",
  "inputs": {"minProducts": 1, "maxProducts": 1, "maxImages": 1},
  "formats": [
    {"id": "portrait", "label": "پست عمودی · ۴:۵", "size": "1024x1280", "aspectRatio": "4:5"}
  ],
  "provider": {"service": "gapgpt", "model": "gpt-image-2.6-sunburst", "quality": "high"},
  "prompt": "متن کامل پرامپت اختصاصی قالب؛ این عبارت فقط جای‌نگهدار مثال است",
  "fields": [
    {"id": "productName", "label": "نام محصول", "maxLength": 100},
    {"id": "brand", "label": "برند", "maxLength": 80},
    {"id": "feature", "label": "ویژگی محصول", "maxLength": 240},
    {"id": "price", "label": "قیمت", "maxLength": 60},
    {"id": "orderMethod", "label": "روش سفارش", "maxLength": 160}
  ]
}
```

`sample` خروجی اول آزمایش لافارر است. فایل WebP آن در `public/templates/blue-splash/` قرار دارد. نمونه صرفاً برای انتخاب کاربر است؛ در API تولید به عنوان مرجع استفاده نمی‌شود. برای این قالب هیچ لایه، مختصات صحنه یا موتور موشن لازم نیست.

فایل‌های `templates/caption/*.json` ساختار کپشن را جدا تعریف می‌کنند. دسته‌ها، زیردسته‌ها، اهداف و شبکه‌ها در `templates/catalog.json` قرار دارند. فقط اینستاگرام فعال است. زیورآلات فعلاً قالب تصویری فعال ندارد.

افزودن قالب بعدی: فایل JSON با شناسهٔ یکتا، پرامپت تست‌شده، نمونهٔ متعلق به خودمان و محدودیت‌های واقعی آن اضافه شود؛ در صورت نیاز گزینه‌های کاتالوگ تکمیل شوند؛ سپس سرویس بازخوانی شود. اگر همان ورودی‌ها و خروجی تصویری پشتیبانی شوند، تغییر موتور لازم نیست. قالب جدید با رفتار یا ورودی متفاوت نیاز به بررسی قابلیت موتور دارد؛ صرف اضافه کردن JSON قابلیت تازه‌ای ایجاد نمی‌کند.

تعریف قالب در زمان ایجاد محتوا داخل همان محتوا snapshot می‌شود. تغییر فایل، پیش‌نویس قبلی را بی‌صدا تغییر نمی‌دهد. سقف عمومی سه محصول است، ولی قالب اسپلش آبی مشخصاً تک‌محصولی است. تغییر اطلاعات کپشن، تصویر موجود را دوباره تولید نمی‌کند؛ ساخت دوبارهٔ تصویر اقدام مستقلی با تأیید کاربر است.

نسخهٔ عمومی با `APP_EDITION=content-v1` اجرا می‌شود؛ نبود این متغیر هم همین نسخه را انتخاب می‌کند. کد ویدیوی قدیمی در حالت داخلی `studio-internal` باقی می‌ماند. مسیرهای قدیمی دریافت/ساخت/بازبینی ویدیو در نسخهٔ عمومی بسته‌اند. انتقال chunk حفظ شده و محتوای واقعی فایل در سرور بررسی می‌شود.

آزمون: `node scripts/test-content-v1.mjs`، با دیتای جدا و مدل شبیه‌سازی‌شده. ۱۸ بررسی API، فایل واقعی، مالکیت، تکرار درخواست و اصلاح کپشن. typecheck/build نیز پاس شده‌اند. کارت قالب و مراحل انتخاب در نمای موبایل مرورگر دیده شدند؛ ارسال فایل از ابزار خودکار مرورگر به مشکل نشست ابزار خورد، بنابراین ادعای تأیید سرتاسری روی موبایل واقعی نداریم. تولید واقعی جدیدی در توسعه انجام نشد؛ شواهد تصویری همان دو تست پذیرفته‌شدهٔ قبلی‌اند.

## به‌روزرسانی مسیر و قالب مچ

مسیر فعلی: پلتفرم ← گرید قالب‌ها با جست‌وجو ← هدف ← قالب کپشن ← اندازه. دسته و زیردسته در JSON قالب می‌مانند و کاربر آن‌ها را انتخاب نمی‌کند. فیلدهای `tags` و `description` در جست‌وجو همراه نام قالب استفاده می‌شوند.

قالب `wrist-window-light` نسخهٔ ۳ شامل انتخاب متناسب نوع دست و رفع ابهام، تشخیص تناسب تک‌تک محصولات، تأیید حذف موارد خارج از قالب و پرامپت مچِ تکیه‌داده روی پارچه است. نمونهٔ فعلی خروجی تست واقعی تک‌عکس است. نمونهٔ اصلی حاوی دستبند و انگشتر بود؛ انگشتر باید حذف شود، نه به دستبند دوم تبدیل شود. کنترل کیفیت فقط محصولات انتخاب‌شده را مطالبه می‌کند. یک خروجی دیده‌شده تضمین تکرارپذیری نیست.
