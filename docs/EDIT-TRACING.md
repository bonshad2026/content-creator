# ثبت و بازپخش محلی تصمیم‌های ادیت

وضعیت جدید مرحلهٔ دوم در `EDIT-EXECUTION.md` است: بازپخش تابع کامل resolveEditTurn نیز اضافه شده و سؤالِ نمونهٔ واقعی حفظ می‌شود. متن زیر گزارش مرحلهٔ اول و حدود ابزار اولیه است.

تکمیل مسیر زیرنویس: traceهای دستی جدید نیز ورودی شامل شواهد را ثبت می‌کنند؛ replay با executeCaptionChanges تراکنش و وضعیت ذخیره‌شده را مقایسه می‌کند و caption.completed را پایان می‌شناسد. trace دستی قدیمی که assets ندارد، همچنان فاقد دادهٔ کافی برای این بازپخش است؛ دادهٔ تاریخی حدس زده نمی‌شود.

مرحلهٔ ۱ از طرح ممیزی ۲۰۲۶/۱۱/۲۱. هدف این تغییر مشاهده‌پذیری است؛ پرامپت، effort، قواعد مکالمه، انتخاب رسانه و fallback رندر هنوز تغییر نکرده‌اند. سه شکست گزارش ممیزی همچنان قابل بازپخش‌اند.

## دادهٔ ثبت‌شده

مسیر خصوصی: `DATA_DIR/edit-traces/<editId>/<traceId>/events.jsonl`. هیچ API یا مسیر عمومی اضافه نشده است. شناسه‌های تشخیصی نیز از پاسخ چت و job حذف می‌شوند.

- تحلیل: پیام‌ها، فایل‌ها و وضعیت قبل از تحلیل، نسخهٔ مبنا، پیشرفت، مصرف و خطا. ورودی داخل صف ثبت می‌شود تا پیام و فایل تازه نیز در اسنپ‌شات باشند.
- مدل: پارامترها و ترتیب کامل پیام‌های ارسالی، پاسخ خام SDK، finish/usage، تلاش‌های برنامه برای parse/retry و نتیجهٔ نرمال‌سازی.
- تصویر: data URL فریم به blob با SHA-256 تبدیل می‌شود؛ ابزار محلی همان URL را بازیابی و هش را کنترل می‌کند. blob مشترکِ تلاش‌های یک trace دوباره ذخیره نمی‌شود.
- گفتار: تنظیمات Whisper، اندازه/هش WAV، پاسخ خام شامل confidence و شواهد پس از فیلتر. فایل خام و WAV کپی نمی‌شوند. هش منبع خام هنگام بازرسی جدید ثبت می‌شود؛ فایل‌های قبلاً بازرسی‌شده دوباره پردازش نمی‌شوند، اما شواهد ذخیره‌شده و فریم‌های واقعاً ارسالی ثبت می‌شوند.
- کش: استفادهٔ مجدد صریح است؛ trace مبدأ در صورت موجود بودن ارجاع داده می‌شود. پاسخ تاریخی ناموجود با پاسخ ساختگی پر نمی‌شود.
- تصمیم: پیشنهاد، ورودی/نتیجهٔ اعتبارسنجی، انتخاب نهایی، تأیید، سؤال و پیام تحویل‌شده. تأیید/رد، لغو درخواست و لغو ادیت trace مستقل دارند.
- رندر: درخواست و رد شدن پیش‌شرط‌ها، پیوند به تحلیل و نسخه، اسنپ‌شات job، timeline/settings/captions واقعی، آرگومان‌های encoder، مرحله‌ها و هش/مشخصات خروجی یا خطا. worker همان trace صف را ادامه می‌دهد. وقفهٔ تحلیل هنگام restart نیز بدون تکرار پولی ثبت می‌شود.
- محیط اجرا: نسخهٔ Node و هش فایل‌های مربوط در زمان بارگذاری ماژول؛ نسخهٔ قدیمی کد خودکار اجرا نمی‌شود.

کلید، cookie، authorization و session map نباید به این ماژول داده شوند؛ فیلدهای حساس شناخته‌شده و رشتهٔ کلیدهای محیطی شناخته‌شده نیز حذف می‌شوند. گزارش شامل گفتار و فریم خصوصی است و زیر پوشهٔ ignored داده می‌ماند. خرابی ذخیرهٔ trace هشدار می‌دهد؛ نتیجهٔ تحلیل یا تعداد درخواست مدل را تغییر نمی‌دهد.

## بازپخش آفلاین

```powershell
node scripts/replay-edit-trace.mjs EDIT_ID TRACE_ID --data-dir data/test-out/template-ui-review
npm run test:trace
```

فرمان اول مدل، شبکه یا FFmpeg را فراخوانی نمی‌کند. هش فریم‌ها را کنترل و نرمال‌سازی پاسخ، اعتبارسنجی شواهد/مکالمه و برنامه/زیرنویس رندر را، هرکدام که ثبت شده باشند، روی **کد فعلی** تکرار می‌کند. خروجی فقط نتایج و شمار رخدادهاست، نه متن خصوصی.

`matched` یعنی نتایج همین بررسی‌های قطعی برابر بوده‌اند؛ اثبات فهم درست مدل، کیفیت ادیت یا موفقیت job نیست. `terminalEvent` پایان کار را جدا نشان می‌دهد. trace بدون ورودی محاسبهٔ کافی، `not-replayable` با exit code 2 می‌دهد؛ اختلاف exit code 1 دارد. اجرای کامل HTTP/state transition یا استنتاج دوبارهٔ مدل بازپخش نمی‌شود. تفکیک مجری تغییر در مرحلهٔ ۲ باید این مرز را گسترش دهد.

«پاسخ خام» دادهٔ برگشتی SDK است؛ header احراز هویت و رفت‌وبرگشت‌های داخلی SDK ذخیره نمی‌شوند. retry موجود برنامه ثبت می‌شود؛ تلاش‌های خودکار داخلی SDK جدا ثبت نمی‌شوند.

گزارش‌های بی‌فعالیت پس از `TRACE_RETENTION_DAYS` روز، پیش‌فرض برابر `RAW_RETENTION_DAYS` یا ۷ روز، در پاک‌سازی ساعتی موجود حذف می‌شوند. چت، فایل اصلی و خروجی دست‌نخورده می‌مانند. صفر یعنی نگه‌داری نامحدود. ارجاع کش به trace حذف‌شده ممکن است باقی بماند؛ دادهٔ کش در trace نوبت جدید نیز ثبت می‌شود.

## شواهد و وضعیت اجرا

تست‌ها از SDK ساختگی، API محلی با تحلیل تزریقی و صوت/تصویر مصنوعی استفاده می‌کنند؛ هیچ درخواست پولی یا ادیت جدید از ویدیوی کاربر انجام نشده است. بازیابی دقیق ورودی چندرسانه‌ای، حذف کلیدها، جدایی traceها، خرابی دیسک، دست‌کاری blob، کش، خطا، وقفهٔ restart، پیوند job و بازپخش timeline/captions بررسی شده‌اند. تست رندر، خروجی واقعی مصنوعی را decode و اندازه/صدا/زمان را کنترل می‌کند.

نتیجهٔ نهایی این مرحله: ۶۵ تست UI/core، ۷۷ بررسی API/template/render، ۱۳ بررسی trace، ۶ بررسی نگه‌داری داده و ۶ بررسی parse/repair پاسخ، همگی آفلاین، پاس شدند؛ typecheck نیز پاس شد. CLI روی trace واقعی مسیر API با تحلیل تزریقی اجرا شد و اعتبارسنجی شواهد و مکالمه را برابر بازپخش کرد. سه مورد ممیزی دوباره اجرا شدند و همان شکست‌های قبلی را نشان دادند؛ این نتیجه عمداً به‌عنوان رفع مشکل گزارش نمی‌شود.

در این مرحله سرویس اصلی/پیش‌نمایش restart نشده است؛ فعال شدن trace در سرویس در حال اجرا به راه‌اندازی بعدی نیاز دارد. UI تغییر نکرده و build تازه منتشر نشده است.
